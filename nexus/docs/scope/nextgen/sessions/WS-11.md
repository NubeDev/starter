## Isolation note (RLS vs route-pinning)

The reused `starter-prefs` `PgPrefsStore` runs queries directly on its pool and does
**not** set the `app.tenant_id` GUC, so the nexus RLS-GUC pattern (`tenant_tx`) does
not bind it. Cross-tenant isolation is instead enforced at the route layer: every
nexus prefs handler pins `workspace_id = principal.tenant_id` and the store filters
**every** read/write by `(user_id, workspace_id)`, so a caller can only ever touch
its own tenant's rows. The `?org=` query param the starter router honours is not
exposed through the nexus routes. This is equivalent isolation to RLS for this table
(the discriminator is in the key, not a separate column), achieved without
duplicating the starter store's ~150 lines of column codecs. Recorded as the chosen
trade-off; a follow-up could push the GUC into the starter store upstream.

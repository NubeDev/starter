## Assumptions / deviations / follow-ups

- **Retention is a single global horizon** (`NEXUS_AUDIT_RETENTION_DAYS`, default 365d), not per-kind —
  one auditable number beats a matrix nothing needs yet; per-kind is a fast-follow (the definer fn would
  take a kind filter). Undo only reaches an actor's most recent group, so retention never truncates a
  reachable undo step.
- **GDPR forget is actor-scoped** (`forget_actor`): it scrubs the *content* a subject produced but keeps
  the audit fact (who/when/op), per the SPI `forget` contract's reasoning — a regulator still needs to
  see an action occurred. The resource-scoped trait `forget` remains for resource erasure.
- **Delete-inverse / `clone_with` deferred** (honest `Error::Invalid`): store insert mints a new id,
  which would orphan panel/grant/pool-cache refs. Needs an id-stable insert in the WS-05 dashboard and
  WS-08 datasource stores (out of lane). See TODOs.md [2026-06-09 23:25] WS-12.
- **Pre-existing `grant_gate_test.rs` `NewDashboard` drift** (missing `icon`/`accent` from migration
  0006) is independent of WS-12 (verified via `git stash`); only the `changelog:` field add is mine.
  See TODOs.md [2026-06-09 23:25] WS-12.
- Per ROADMAP §6a C6 this is substrate-only: other workstreams add their own `record(...)` call after
  their mutations and append their kind to `KNOWN_MUTABLE_KINDS` in the same PR.

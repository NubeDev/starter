## Assumptions / deviations / follow-ups

- Dry-run constructs `QueryRunner::new()` per request (idempotent registration; stateless runner)
  rather than adding a field to the shared `AppState`/`main.rs` (WS-09 lane). Keeps WS-06 in-lane.
- Config JSON Schemas are hand-authored next to each builder (the builders deserialize with serde,
  which carries no schema). They describe the same fields the `*Config` structs deserialize.
- `FlowMetrics` omits throughput (rows/batches): the manager spawns the engine stream but does not
  instrument the real output sink, so any count would be fabricated (F0). Surfaced running /
  last_started_at / last_error only.
- The old `FlowFormDialog.tsx` + `flowDraft.ts` (+ its test) are now unreferenced by the page but
  left in place (authored by an earlier flows slice; not this WS's to delete). The raw-JSON
  authoring path lives on as the builder's "Raw JSON" escape-hatch tab.
- Builder opens for *creating* a flow. Opening an existing flow for visual *editing* (parseGraph is
  ready, needs an update mutation + entry point) is a follow-up.

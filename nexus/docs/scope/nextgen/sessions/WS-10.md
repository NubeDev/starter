## Re-verification (ROADMAP §0)

Re-grepped WS-10's "Current state" / dependency claims against branch tip `nexus-gaps`:

- **C2 binder (WS-03 dep) — PRESENT and richer than the doc assumed.** The binder lives at
  `nexus-store/src/query/bind/` (`mod.rs`, `context.rs`, `bound.rs`, `scan.rs`, `vars.rs`,
  `time_macros.rs`, `dialect.rs`, `error.rs`). `BindCtx` already carries `params: BTreeMap<String,
  ParamValue>` and `host_tokens: HostTokens { caller_tenant_id, caller_user_id }` (the WS-10
  reserved fields, decision D3). `$caller_tenant_id`/`$caller_user_id` are bound from host tokens
  and **rejected if present in caller input** (`vars.rs::reject_host_token`,
  `scan.rs::expand_bare`). A `$param` is bound as a `$N` arg via `vars.rs::expand_param`. So the
  kinds layer does **not** build a binder — it only needs to populate `BindCtx.params` +
  `host_tokens` and call `bind()`. The acceptance criterion "host token cannot be overridden by
  caller" is already enforced by the binder; WS-10 adds a kinds-level test that proves it.
- **`run_request` / `QueryIdentity`** in `nexus-store/src/query/request.rs` already maps a wire
  `QueryRequest` + `QueryIdentity` into a `BindCtx` (host tokens from identity) and runs it. WS-10
  adds a sibling `run_kind_request` that also fills `params`.
- **`QueryRequest` DTO** (`nexus-spi/src/dto/query/run.rs`) is the C7 single-owner contract.
  Per C7, WS-10 adds its `kind` + `params` fields as a **small additive append** (optional fields),
  not a restructure — sql-mode stays the default, kind-mode is opt-in.
- **No `kinds/` anything exists in nexus yet** — green field for the registry/loader/pack.
- **`PanelQuery`** (`ui/src/data/types.ts:34`) is `{datasourceId, sql, params?}`. WS-10 widens it
  to a discriminated union (sql-mode | kind-mode) as a 🔶 append.
- Rubix reference pack confirmed at `rubix/extensions/com.nubeio.rubixos/kinds/` (manifest
  `block.yaml`, `*.sql` + `*_params.json` + `*.cache.yaml`). Field shape ported, nexus-native.

No WS doc drift required beyond noting the binder is already host-token-complete; the WS-10 doc's
§4.2 "the binder is the same component" is satisfied as-built.

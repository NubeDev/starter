"Migration: none"). The new config simply rides in the same opaque `layout` blob.

## Assumptions / deviations

- Editor is presented as a full-screen dialog (Grafana opens a dedicated editor route; a dialog is
  the smallest reachable surface that satisfies "full-screen editor + live preview" without adding
  a new route + router-ownership concerns that belong to WS-05). The side `PanelProperties` is kept
  as the lightweight inline editor; the "Edit" affordance opens the full editor.
- Unit-as-`quantity` (WS-11 coupling) is intentionally NOT pre-built here: the WS doc says add
  `quantity`/`storedUnit` *with* WS-11 so the model lands once. WS-11 is later in the queue. WS-04
  ships a plain client-side unit registry + display unit; WS-11 will layer quantity/conversion on
  top. Noted, not a blocker.

## Follow-ups

- **WS-11 (Units & datetime prefs):** layer `quantity`/`storedUnit` + convert-on-read onto the
  unit registry shipped here (display-only today). The `FieldDisplay.unit` id is the seam.
- **Stat decimals:** `MetricCard` (starter-ui-dashboard) renders `value: number` and rounds to an
  integer, so the stat panel honours unit symbol (prefix/suffix) but not per-field `decimals`.
  Not forked — gauge/table fully honour decimals/units/mappings, which satisfies the acceptance
  criteria. A future WS could add a decimals-aware stat renderer if product wants it.
- **Transforms reordering:** the Transforms tab supports add/edit/remove; drag-reorder of steps is
  a nice-to-have left out (pipeline order = list order, editable by remove/re-add).
- **PanelProperties overlap:** the lightweight side panel still edits type/title/datasource/SQL/
  x/value; the full editor is the superset. If product prefers a single surface, the side panel
  could be retired in favour of always opening the editor.

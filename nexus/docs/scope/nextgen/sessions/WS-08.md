## Deviations / deferrals

- **The connector breadth itself (MQTT/Modbus/HTTP-REST/Prometheus/Kafka) is NOT landed this
  session.** It is logged as a blocker in TODOs.md with concrete options. Reasoning (no-hacks rule):
  - The vendored ArkFlow is connector-trimmed, so MQTT/Modbus need **new gated client deps**
    (`rumqttc`/`tokio-modbus`) — a feature-gate/binary-weight decision HOW-TO-CODE §9 reserves as an
    explicit "ask, don't guess" item.
  - The datasource record is **Postgres-shaped** (`host/port/database/db_user/secret`). MQTT needs
    topic/QoS; Modbus needs unit-id/registers. Carrying kind-specific config means either reshaping
    the record or adding a JSON-config column (migration `1301`) **whose shape couples to WS-10's
    datasource-kind declaration format — which is Wave 2 and NOT YET BUILT** (WS-10 shipped only
    query-kinds). The WS-08 spec explicitly says "WS-10 owns the declaration format; this WS supplies
    the builders." Inventing that format here would redefine a shared contract I don't own.
  - *Query* connectors (HTTP-REST/Prometheus) additionally require reshaping the deeply
    `PgPool`-typed query core (`query/run.rs`, `datasource_pools` → `PgPool`) to be
    source-polymorphic — that reaches into WS-03's binder/runner, out of lane.
  - The acceptance criterion "a live panel/flow ingests from MQTT or Modbus end-to-end" needs a live
    broker/device to verify, which I cannot stand up verifiably in an unattended run.
- **C6 (audit/undo `Reversible` for the datasource kind)** is deferred: WS-12 (the changelog/undo
  substrate) has not run yet, so there is nothing to register against. Same deferral WS-07 recorded.
  Datasource create/update/delete handlers are unchanged on the recording front.

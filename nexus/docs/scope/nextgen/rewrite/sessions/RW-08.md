## Design (lane-respecting)

§4 owns `nexus-engine/src/flow/**`, `backend/tests/soak/**`, `BACKPRESSURE.md`.
`core/pipeline.rs` is RW-01/03 lane and was NOT touched. Metrics + failure policy
are implemented as **metered wrapper nodes** around the flow's real source/sink,
installed via a per-flow registry composed in `flow/metered/registry.rs` from the
public `Registry` + `native_registry()` + node-trait APIs. The flow manager knows
each run's exact source/sink type names, so it overrides just those two builders
(delegating to an inner native registry, then wrapping); processors and unused
built-ins keep their native builders. The pipeline drives the wrapped nodes
unchanged — zero core edits.

## Assumptions / deviations

- **Soak location.** The spec says `backend/tests/soak/`; this workspace has no
  top-level `backend/tests/` (tests are crate-local). Placed under
  `crates/nexus-api/tests/soak/` — the crate with the docker + datasource-resolve
  machinery the soak needs.
- **DB-kill chaos.** `with_database()`'s `ContainerGuard` does not expose
  pause/stop, so the chaos case induces a real DB-side fault (DROP the destination
  table mid-run) rather than a container kill. Same observable contract: writes
  fail → policy acts → flow halts without panic/silent-loss → counters reconcile.
  Documented in BACKPRESSURE.md.
- **channel_depth** is an approximate in-flight gauge (batches read minus sink
  writes, clamped ≥0), since the wrapper cannot see inside the pipeline's private
  channel. Documented as coarse on the DTO.

## Scope (from RW-05_FEDERATION.md)

1. `nexus-engine/src/federation/` — a `FederatedQuery` runner registering a
   TableProvider per referenced datasource/file, planned by DataFusion's own
   catalog resolution, executed under the QueryRunner caps + a real input-side
   `MemoryPool` bound.
2. Dispatch seam in the query route: single datasource → existing push-down path
   untouched; multi-datasource or file kind → federation runner. Backward-compatible
   DTO (additive `sources` map).
3. New `parquet` / `csv` datasource kinds in the WS-08b declarative pack.
4. Tenancy: a federated query may only touch datasources the caller's tenant owns.

## Dependency decision (scope step 1, FIRST ACTION)

Evaluated `datafusion-table-providers` + `datafusion-federation` together.

REJECTED `datafusion-table-providers` for the Postgres provider:
- Latest (0.11) needs datafusion `^53` + arrow `^58`; we are pinned at 47/arrow55.
  The only release matching `^47` is 0.5.0 (old).
- Its Postgres provider is built on `tokio-postgres` + `bb8` — a SECOND Postgres
  client stack. Roadmap §8 forbids a second client stack; RW-04 deliberately chose
  sqlx's `PgCopyIn` over tokio-postgres for exactly this reason. Adopting it would
  reintroduce the stack RW-04 avoided.
- A datafusion 47→53 bump to reach a current table-providers would edit RW-02/03/04
  frozen lanes (sql processor, sinks, engine `Cargo.toml`) — out of lane, high risk,
  and §6's "pin is free" does not license touching other RWs' frozen code from RW-05.

DECISION: hand-write a sqlx-backed Postgres `TableProvider` reusing the existing
audited cred/pool path, and use DataFusion's NATIVE Parquet/CSV (`object_store`
0.12 + `parquet` 55, both already in the lock via datafusion 47, both §8-approved)
for file kinds. No datafusion bump, no second client stack, no new heavy dep.

## Task breakdown

Scope step 1 — engine `nexus-engine/src/federation/`:
- `source.rs` — `FederatedSource` enum (Postgres/Parquet/Csv) + `PostgresConn`.
- `identifier.rs` — `validate_identifier` (`[A-Za-z_][A-Za-z0-9_]*`) for table names.
- `rows_to_batch.rs` — NDJSON → Arrow `RecordBatch` (Postgres `to_jsonb` rows → batch).
- `postgres_table.rs` — hand-written sqlx `TableProvider`; eager schema fetch, per-scan
  `LIMIT min(limit, max_fetch_rows)` input bound (no second client stack).
- `context.rs` — memory-bounded `SessionContext` (`GreedyMemoryPool` = input-side bound),
  registers each source as the bare table `ds_<alias>` so DataFusion's OWN catalog resolves
  names at plan time (no SQL string-scraping).
- `mod.rs` — `FederatedQuery::run(caps)`: deadline timer, read-only `SQLOptions`
  (no DDL/DML/statements), collect under `CapState` (output rows/bytes/wall-clock + truncation),
  shape to `QueryOutcome`.

Scope step 2 — dispatch seam (API):
- DTO (additive, DTO-first): `QueryRequest.sources: Vec<FederatedSourceRef>` (`#[serde(default,
  skip_if empty)]`) + `FederatedSourceRef{alias, datasource, table?}`. openapi.json + UI
  codegen regenerated (both +32 lines, purely additive; UI typecheck green).
- `cache/key.rs` — cache key folds in sorted `sources` so a federated result never collides
  with the same SQL on the push-down path.
- `federation/{mod,resolve,run}.rs` — `is_federated` predicate, `resolve_sources` (tenancy +
  audited decrypt), `run_federated` (literal SQL, no `$N` binder — DataFusion can't consume it),
  `run_cached` (result cache + quota admit), `respond` (transport seam).
- `routes/datasources/query.rs` — one-line branch: `is_federated` → `federation::respond`,
  else the existing push-down path UNCHANGED (byte-identical; proven by the dispatch unit test).

Scope step 3 — declarative pack: `parquet`/`csv` kinds in `manifest.yaml` +
`parquet_config.json`/`csv_config.json` (Surface::Query, path-only, no secrets, connect probe).
`GET /datasources/kinds` lists them automatically (registry-driven). Pack lint + load test
updated to 4 kinds.

Scope step 4 — tenancy: `resolve_one` fetches via RLS-scoped `datasource::get` (cross-tenant id

## Assumptions / deviations / follow-ups

- Dependency decision (FIRST ACTION) recorded above: rejected `datafusion-table-providers`
  (second Postgres client stack + datafusion `^53` bump, both forbidden); hand-wrote a sqlx
  `TableProvider` and used DataFusion's native Parquet/CSV. No new heavy dep, no datafusion bump.
- Macros/variables (`$__timeFilter`/`$var`) are deliberately NOT applied on the federated path:
  the push-down binder emits Postgres `$N` placeholders for sqlx, which DataFusion cannot
  consume. A federated statement runs literally against the `ds_<alias>` tables; the read-only
  `SQLOptions` keep it a pure join (DDL/DML/statements rejected). Documented in `run.rs`.
- BLOCKER deferred to RW-04 (logged in TODOs.md): a file datasource cannot be *persisted* —
  `nexus_datasources` (migration 0001) is Postgres-shaped (no `config`/`path` column, secret
  NOT NULL). So `resolve::resolve_one`'s file arms return an explicit `Invalid` (loud, never a
  silent drop) until RW-04 adds a nullable `config jsonb` + nullable secret. Postgres↔Postgres
  federation is fully wired E2E; the engine's file support is proven at the engine seam.
- Pre-existing branch breakage (NOT RW-05): `tests/routes/identity/wiring_test.rs` (serve::router
  arity) and `tests/routes/authz/grant_gate_test.rs` (NewDashboard new fields) fail to compile
  from other in-flight workstream commits on `nexus-rewrite`; untouched by this session.

## Assumptions / deviations / follow-ups

- Global vs tenant table: extension insights are **global** (`nexus_extension_insights`, no
  RLS), mirroring `nexus_extension_query_kinds` — an extension installs once deployment-wide
  (admin-gated). The script still runs only against the caller's own result rows at query
  time, so a global definition never touches another tenant's data.
- Namespace ownership validation lives in nexus-api `contribute_insights.rs` (the boot/lint
  lane), NOT in `starter-ext-host` validate.rs (out of lane). Reused the fixed
  `CleanupKind::WarehouseTable` rather than editing the kernel enum (no kernel change).
- Scope items 2–4 (sources/sinks/`ingest.write`+`ingest.read_batch`/engine extension nodes/
  `ingest.*` authz) deferred — logged to TODOs.md (2026-06-10 RW-07) with handoff. The
  process-runtime `ingest.write` e2e and channel-full backpressure acceptance bullets belong
  to that follow-up.
- The hello e2e `DELETE …?purge=true` cleanup assertion (acceptance bullet 1) is covered by
  the `InsightCleanupProvider` path; the existing hello e2e extension was not extended with a
  new purge assertion this pass — folded into the same deferral note for the data-plane e2e.

# RW-02 — Port nodes onto the core engine (DataFusion direct)

Status: Done
Started: 2026-06-10 02:30 UTC
Finished: 2026-06-10 03:25 UTC

## What landed

Native ports of every nexus source/processor/sink onto the RW-01 `core::{Source,
Processor, Sink}` traits, plus native replacements for the ArkFlow built-ins the
runners use. Additive: the ArkFlow registrations stay alive in parallel (RW-03
cuts the runners over and deletes them). `cargo test -p nexus-engine` green (40
tests across lib + 14 integration binaries); `cargo check --workspace` and
`cargo test --workspace` green; `cargo clippy -p nexus-engine --all-targets`
clean.

### New files (RW-02 owned lanes: `source/`, `sink/`, `processor/`, `arrow_json.rs`)

Processors (`src/processor/`):
- `mod.rs` — barrel.
- `json_to_arrow.rs` — `arrow-json` Decoder via `datafusion::arrow::json`.
  Schema-stability per roadmap §6: declared schema wins, else infer-on-first-
  batch-then-lock; a later batch whose column type drifts is a processor error,
  never a silent re-inference.
- `declared_schema.rs` — parses an optional `{ "fields": [{name,type}] }` schema
  from flow config (arrow `Schema` is not serde-deserialisable without a feature
  flag; the flow-facing format is a small closed primitive set instead).
- `sql.rs` — DataFusion `SessionContext`, registers the batch as `flow` (or
  `table_name`), read-only `SQLOptions` (no DDL/DML/statements), concat multi-
  batch results into one.

Sources (`src/source/`):
- `memory.rs`, `generate.rs`, `http_poll_source.rs`, `simulator_source.rs` —
  native ports; JSON sources emit a one-column carrier batch (`__value__` Utf8)
  that `json_to_arrow` unwraps, mirroring ArkFlow's binary-value-field flow.
- `interval.rs` — ms-aware cadence parser (`5ms`/`30s`/`15m`/`1h`); kept in the
  source lane so the shared `time::parse_interval` (still used by the live
  ArkFlow sources) is untouched.

Sinks (`src/sink/`):
- `drop_sink.rs`, `stdout.rs` — trivial.
- `collector_sink.rs`, `sse_sink.rs` — reuse the existing `store::RunSink` /
  `broadcast_store::LiveChannel`, so caps, the truncation flag, the breached-cap
  token cancel, and the monotonic SSE seq numbers stay bit-identical.
- `postgres_sink.rs` + `pg_insert.rs` — bound-parameter insert (never string-
  concatenated); pool opened lazily on first write (the native trait has no
  `connect`), closed on `close`.

Registry + bridge:
- `src/native_registry.rs` — `native_registry() -> core::Registry` with every
  built-in under the same string names stored flow configs use (`memory`,
  `generate`, `http_poll`, `simulator`, `json_to_arrow`, `sql`, `collector`,
  `sse`, `postgres`, `drop`, `stdout`).
- `src/arrow_json.rs` — added `JSON_VALUE_FIELD`, `json_carrier_batch`,
  `json_carrier_docs` (the source↔json_to_arrow carrier convention).

Shared (🔶 append-only): `src/lib.rs` — `pub mod processor; pub mod
native_registry;` + `pub use native_registry::native_registry;`.

### Tests (mirrored, declared in Cargo.toml)

- `tests/native/pipeline_test.rs` — e2e parity: `memory → json_to_arrow → sql →
  collector` on the native registry returns the same rows/columns/truncation as
  the ArkFlow query seam (`tests/runner/query_test.rs`).
- `tests/processor/{json_to_arrow,sql}_test.rs` — typed-column parsing, schema-
  stability (drift rejected), declared-schema pin; SELECT ordering, empty-batch
  no-op, DML rejected, custom table name.
- `tests/source/{memory_native,generate_native}_test.rs` — finite-end semantics,
  count bound, batch_size.
- `tests/sink/{sse_sink_native,collector_sink_native}_test.rs` — monotonic seq,
  caps/truncation + token cancel.

## Assumptions / deviations

- `arrow-json`: used via the `datafusion::arrow::json` re-export rather than a
  separate `arrow-json` crate dep (the spec said "add datafusion + arrow-json").
  `datafusion` is already a direct dep; using its re-export guarantees exactly
  one Arrow in the tree (roadmap §8), which a separate `arrow-json` dep could not.
- Native `sql` uses a plain DataFusion `SessionContext`. ArkFlow's vendored `sql`
  also registers `datafusion_functions_json` UDFs + a custom udf set. No stored
  flow / existing test uses those, so the native processor omits them rather than
  pulling a JSON-UDF dep the roadmap §8 hasn't approved. Logged to TODOs.md for
  RW-03 to confirm at cutover.
- Declared-schema format is a flow-facing primitive field list, not raw Arrow
  JSON. RW-04 (warehouse sinks) may extend it.

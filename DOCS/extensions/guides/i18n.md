# Localising your extension

Reference for extension authors who ship strings through the
notes-host i18n pipeline. Ten minutes top-to-bottom.

> Source-of-truth ceilings:
> [`DOCS/user/scope/SCOPE.md`](../../user/scope/SCOPE.md) R5/R9 and
> [`DOCS/extensions/scope/SCOPE.md`](../scope/SCOPE.md) R11/R13. This
> guide describes the contract; those scopes own it.

## TL;DR

```yaml
# block.yaml
id: com.acme.widgets
v: 1
requires:
  - "@nube/starter-ui-core/preferences"
  - "@nube/starter-ui-core/i18n"
contributes:
  ui:
    entry: ui/remoteEntry.js
    exposes:
      - { name: WidgetsPanel, module: ./WidgetsPanel, slot: sidebar }
  i18n:
    catalogs:
      en: i18n/en.json
      es: i18n/es.json
```

```jsonc
// i18n/en.json
{
  "greeting":     "Hello, {name}!",
  "unread":       "{count, plural, one {# unread widget} other {# unread widgets}}",
  "today":        "Today is {date}"
}
```

```ts
// inside your panel
import { useHostTranslate, useHostFormatters } from "@nube/starter-ext-sdk-ts";

export function WidgetsPanel() {
  const t = useHostTranslate();
  const { formatDate, formatQuantity } = useHostFormatters();
  return (
    <section>
      <p>{t("greeting", { name: "Sam" })}</p>
      <p>{t("unread", { count: 3 })}</p>
      <p>{t("today", { date: formatDate(Date.now()) })}</p>
      <p>BBQ: {formatQuantity(22.4, "temperature", "celsius")}</p>
    </section>
  );
}
```

That is the entire surface. The rest of this doc is the rules and the
reasoning.

## The contract

The host owns one `<PreferencesProvider>` and one `<IntlProvider>`.
Both Context objects are exposed to extensions as singletons under
the `@nube/starter-ext-ui` host manager:

| Singleton id | What it carries |
|---|---|
| `@nube/starter-ui-core/preferences` | `PreferencesContext` — resolved prefs + `setPreferences` |
| `@nube/starter-ui-core/i18n`        | `IntlContext` — host language + `IntlShape` + manifest |

Your `remoteEntry.js`'s `init` factory declares both in `singletons:`,
the host refuses to load on a major mismatch (`singleton-mismatch`
lifecycle, `extension.singleton_mismatch` telemetry), and a minor
drift loads with `extension.singleton_minor_drift`. See
[D-NP.10](../../../examples/notes/user-pref.md#d-np10---semver-promise-for-the-singleton-contract)
for the semver promise.

## Catalog files

- **Path:** `i18n/<lang>.json`, one file per language.
- **Format:** flat ICU MessageFormat. Keys are dotted strings; values
  are ICU templates with named placeholders (`{name}`,
  `{count, plural, …}`, `{when, date, short}`). No nested objects —
  the codegen pass for `MessageKey` types is flat by design
  ([D-NP.7](../../../examples/notes/user-pref.md#d-np7---catalog-format-is-flat-icu-messageformat)).
- **Namespacing:** keys are auto-prefixed with your extension id at
  registration time. `greeting` in `com.acme.widgets/i18n/en.json`
  registers as `com.acme.widgets.greeting`. Fully-qualified keys you
  write yourself pass through verbatim. Keys that target *another*
  extension's namespace are dropped at registration and emit
  `extension.catalog_key_collision`.
- **Lazy-load:** only the active language is fetched. Switching
  language triggers a new fetch for the new language; you never pay
  for languages your operator does not use.

The workspace-wide gate `pnpm -w run check:i18n` walks every
`i18n/<lang>.json` and asserts (a) every non-en catalog matches the
en key set, (b) every key resolves to a non-empty string, (c) ICU
placeholders match across languages. A missing key fails CI.

## The SDK hooks

All three live in `@nube/starter-ext-sdk-ts`. Import directly — no
provider plumbing on your side; the host's federation runtime wires
the bindings before your `init` runs.

### `useHostPrefs()`

Returns `ResolvedPreferences` — every field concrete (no
`auto`/`null`). Use the shape; never re-resolve preferences yourself.

### `useHostTranslate()`

Returns a translator backed by the host's `IntlShape`:

```ts
const t = useHostTranslate();
t("greeting", { name });          // → "com.acme.widgets.greeting"
t("starter.settings.title");      // → kept verbatim (already qualified)
```

- Bare keys auto-prefix with your extension id.
- The `MessageKey` type is generated from the union of platform keys
  + your declared keys; a typo is a TypeScript error.
- A key the catalog does not resolve falls back to the literal id
  (react-intl default) and fires `i18n.message_missing` telemetry so
  platform dashboards can spot the gap. In dev you also get a
  `console.warn` with the missing key.

### `useHostFormatters()`

Returns the five pure formatters bound to the resolved prefs:

```ts
const { formatDate, formatTime, formatNumber, formatCurrency, formatQuantity } =
  useHostFormatters();

formatDate(Date.now());                                  // → AU op: "22/04/2026"
formatQuantity(22.4, "temperature", "celsius");          // → BBQ op:  "72.4 °F"
```

Never inline `Intl.DateTimeFormat(…)` with a hard-coded locale.
That bypasses the operator's preferences and breaks the SCOPE R6
"conversion at exactly one layer per surface" rule.

## Testing

Mount your panel under `<MockHostProvider>` from
`@nube/starter-ext-sdk-ts/testing`:

```tsx
import { MockHostProvider } from "@nube/starter-ext-sdk-ts/testing";

render(
  <MockHostProvider
    extensionId="com.acme.widgets"
    prefs={{ language: "es", locale: "es-MX", /* … */ }}
    catalogs={{ es: { "com.acme.widgets.greeting": "¡Hola, {name}!" } }}
  >
    <WidgetsPanel />
  </MockHostProvider>,
);
```

The helper stands up the same singleton context shape the host uses
in production, so the same hooks resolve to your supplied prefs +
catalog without a network round-trip.

## Locale fallback

`<IntlProvider>` resolves languages by left-truncating BCP-47:
`es-MX` → `es` → `en` floor. The floor is `en`, not the first
available catalog — see
[D-NP.6](../../../examples/notes/user-pref.md#d-np6---locale-fallback-chain-is-left-truncating-bcp-47-floor-en).
The first fallback per session per locale emits `i18n.locale_fallback`
so platform dashboards can spot gaps.

## Multi-tab

A `setPreferences` call fans out to every same-origin tab over a
`BroadcastChannel("starter-prefs")`. Other tabs apply the patch
optimistically and re-validate against the server. You do not need
to subscribe — the host wires this once per page.

## Telemetry summary

| Event | Severity | When |
|---|---|---|
| `extension.singleton_mismatch`     | error | Major singleton mismatch refused load |
| `extension.singleton_minor_drift`  | warn  | Minor mismatch loaded with warning |
| `extension.catalog_key_collision`  | warn  | Extension wrote into another's namespace |
| `i18n.locale_fallback`             | info  | First fallback per session per locale |
| `i18n.message_missing`             | warn  | Key returned the id verbatim (no catalog hit) |
| `prefs.broadcast_dropped`          | warn  | BroadcastChannel post failed |

Names are frozen on merge. Dashboards key off these exact strings.

## What not to do

- **Do not** mount `<IntlProvider>` inside your `remoteEntry.js`. The
  host already mounted one; a second one bundles a second copy of
  the catalog and drifts when the host's language flips.
- **Do not** refetch `/v1/me/preferences` from your panel. Use
  `useHostPrefs()`.
- **Do not** inline `Intl.DateTimeFormat()` with a hard-coded locale.
  Use `useHostFormatters()`.
- **Do not** rename the telemetry events to be "nicer." They are the
  dashboard contract.

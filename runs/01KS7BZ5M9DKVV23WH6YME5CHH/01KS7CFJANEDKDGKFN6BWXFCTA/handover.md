## What you need to know

- `parse_rule_id` (in `nodes/rule_rust.rs`) splits at the **first** `.` so a rule registers as `RuleId { namespace = "iot", name = "sensor.in-range", major = 1 }` and the wire string `iot.sensor.in-range@1` round-trips. Document this convention before Phase 2 packs land — `org.acme.foo.bar@1` would parse as `(namespace="org", name="acme.foo.bar")`, which may surprise pack authors expecting reverse-DNS.
- Several `starter-spi::insights` types are `#[non_exhaustive]` (`Coverage`, `EffectiveCoverage`, `RuleInput`, `Dataset`, `Verdict`, …). I added `from_parts` constructors so out-of-crate code (`starter-insights`, packs) can build them. Honour the pattern for any new field — adding a field stays non-breaking.
- The IoT pack is wired into the sibling `starter-extensions` workspace directly (not via the `Extension` derive / `block.yaml` / `contributes.tools` SDK surface yet). It exposes plain `rules()` / `quality_flags()` functions the host calls during boot, matching the SCOPE language "registered with `RuleRegistry` by an extension's `register()` method". The full SDK-derive flavour (which would let the pack ship as a process / WASM extension) can be layered on later without changing this file.
- `starter-insights` depends on `starter-store-sqlite` only behind the `sqlite` feature, keeping the default dep tree light.
- `verdict.join` weighted mode in `nodes/verdict_join.rs` redistributes errored-input weight proportionally per R-ins-6, but the weight wiring still expects pipeline-level config; Phase 1 has no node-settings surface for it, so the smoke test only exercises `JoinMode::All`. Weighted-mode tests should land alongside Phase 2's pipeline-settings work.
- Sqlite migration uses `sqlx::migrate!("./migrations/insights")` — the path is relative to `starter-insights`'s manifest, same shape `starter-store-sqlite` uses for its own migrations.

Worth raising with whoever owns the extensions SCOPE.

Phase 2 should promote at least one smoke to a real `FlowRunner` once `rule.rust` is contributed to `starter-flow-nodes`'s `NodeKindRegistry` proper — Phase 1 only ships the body, not the registration glue.

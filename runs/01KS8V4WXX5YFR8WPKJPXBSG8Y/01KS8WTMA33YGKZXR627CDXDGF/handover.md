## What you need to know

- `cargo clippy -- -D warnings` is still red on the baseline `examples/flow-agent/src/cache_demo.rs:176` (`manual_clamp`, pre-existing; documented in the slice-A handover). Stage 2 didn't touch it; the in-tree code we added is clippy-clean against the default profile.
- The `manifest.contributes.nodes[].settings_schema` path resolves to a *file path*, but `flow.node.invoke` params expect a `settings` JSON body. The MQTT driver currently reads `params.settings` directly (host plumbs the node's published `settings:` body verbatim); plumbing the engine to forward the schema-validated settings on every invoke is part of the FlowEngine bridge work above.
- The MQTT driver binary lives at `examples/flow-agent/extensions/com.nube.mqtt/Cargo.toml` (workspace member name `mqtt-driver`). The `block.yaml`'s `runtime.bin: bin/mqtt-driver` expects the binary to be staged at `examples/flow-agent/extensions/com.nube.mqtt/bin/mqtt-driver` for in-place loads. For tests we copy `target/debug/mqtt-driver` into the staged tempdir; for production users an example Makefile target (TBD) should `cargo build --release -p mqtt-driver` and `cp` into `bin/`.
- The supervisor's `stream.*` forwarder requires the proxy to have called `subscribe_stream(invocation_id)` BEFORE the child emits any `stream.event`. The proxy enforces this ordering (subscribe-then-issue-call). Notifications for unsubscribed stream ids are dropped with a debug log — there is no per-stream buffering in v0.1.
- `extensions.rs::ExtensionManager::bootstrap` uses `futures::executor::block_on` to drive the initial reload — `flow-agent::server::build` is sync (it runs before the tokio runtime starts in `main`) so we can't `.await` directly. If a future refactor moves `build` to `async`, drop the `block_on` and `.await` the reload.
- `flow_node_error_codes::NODE_BACKEND` (-32060) maps to `NodeError::Backend`, `NODE_CANCELLED` (-32061) to `NodeError::Cancelled`, `INVALID_INVOCATION_PARAMS` (-32051) to `NodeError::InvalidInput`, `NODE_KIND_NOT_BOUND` (-32050) to `NodeError::Domain { code: "node_kind_not_bound", .. }`. The proxy expects the child to serialise the carved error in the JSON-RPC `error` field as a JSON string containing `{ code: i32, message: String }` (the MQTT driver does this via its `send_error` helper).
- `cargo fmt --all` is clean across both workspaces.

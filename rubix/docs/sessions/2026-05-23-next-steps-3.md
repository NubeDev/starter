### Lessons from prior passes (don't relearn these)

- **ai-agent propagator** — only routes **declared trigger slots** into a body's input map. Seeding `ALLOWED_TOOLS_SLOT` as initial state without declaring it a trigger means the body never sees it. The simplest test wire is one trigger slot (`INPUT_SLOT`), no `allowed_tools` configured, relying on the body's dispatch-by-name fallback (per `compute_visible_tools`: "if the model still emits a tool call by name the dispatcher resolves it against the host registry at call time"). ### Path A — Finish the upstream Postgres stores (R2 upstream-first)

Recommended unless the user explicitly says otherwise. Each store
is ~200 lines of mechanical translation against the locked
PgUserStore pattern; ship one per PR with its own testcontainers
test. Order by size:

1. **`PgSessionStore`** — 177 lines. Mirror `SqliteSessionStore`.
   `?N` → `$N`. `sqlx::sqlite::SqliteRow` → `sqlx::postgres::PgRow`.
   `revoked_at` is `TIMESTAMPTZ` not `TEXT (rfc3339)` — sqlx's
   `chrono::DateTime<Utc>` works for both, but be explicit about
   the column type. Add `tests/pg_session_store.rs` mirroring
   `tests/pg_user_store.rs`.
2. **`PgTokenStore`** — 230 lines. Same pattern. The `scopes`
   column is `JSONB` in Postgres (per migration 0003); the Rust
   code that reads/writes it as a JSON-encoded `String` keeps
   working because sqlx coerces JSONB ↔ String at the type seam,
   but the test should assert the column type is `jsonb` to lock
   the migration's intent. Add `tests/pg_token_store.rs`.
3. **`PgTenantStore`** — 397 lines post-refactor. Largest. Migrations
   0005 + 0006 carry the **real semantic translations**:
   - sqlite `slug NOT GLOB '[0-9]*'` → Postgres `slug !~ '^[0-9]'`
   - sqlite `CREATE TRIGGER ... BEFORE UPDATE ... SELECT RAISE(ABORT, ...)`
     → Postgres `CREATE OR REPLACE FUNCTION ... RAISE EXCEPTION ...;
        CREATE TRIGGER ... BEFORE UPDATE ... EXECUTE FUNCTION ...`
   - error matching: sqlite's `e.message().contains("CHECK constraint failed")`
     has no Postgres equivalent text; use `e.code() == Some("23514".into())`
     instead (Postgres SQLSTATE for `check_violation`).

   Add `tests/pg_tenant_store.rs` covering tenants + teams + the
   trigger-enforced immutability.

Full per-piece notes already in
[docs/design/starter-changes/](../design/starter-changes/README.md).
Each PR is small enough to be one focused session.

### Path B — Bootstrap-user + auth wiring against the partial Postgres surface

The user-creation path is unblocked. The rubix side of PR 2 part 2
that depends only on `PgUserStore` (not sessions / tokens / tenants)
can land **now**:

1. New `rubix-admin` subcommand of the agent binary (or a tiny
   second binary in `rubix-agent` — verb-per-file calls for the
   second binary). `rubix-admin bootstrap-user --email --password`
   reads `RUBIX_DSN`, opens a Postgres pool via
   `starter-store-postgres::pool::connect`, applies
   `starter_auth_users::migration::postgres_migration_source()` (so
   it's idempotent on a fresh DB), and calls
   `starter_auth_users::admin::create_admin` against a
   `PgUserStore`. Idempotent: treat `Conflict` as success when
   email + role match.

2. New `mani run bootstrap-user` task wrapping the subcommand.
   Reads `RUBIX_BOOTSTRAP_EMAIL` + `RUBIX_BOOTSTRAP_PASSWORD` env
   vars; fails fast if `RUBIX_DSN` is unset.

3. `boot/migrations.rs` chains `postgres_migration_source()` into
   the existing `migrate(&pool)` plan so the user table exists
   alongside the changelog tables on `cargo run -p rubix-agent`.

What this **does not** unblock: cookie sessions, API tokens,
tenant-scoped authz. Those still need PgSessionStore / PgTokenStore
/ PgTenantStore. So Path B is a partial win — it makes the
bootstrap-user demo flow work end-to-end against Postgres but
leaves the full PR 2 part 2 still gated.

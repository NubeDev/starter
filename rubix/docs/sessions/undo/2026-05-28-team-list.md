# Session 2026-05-28 \u{2014} team.list operator surface

Ships `rubix.team.list`, the missing read verb in the team
surface. Until this slice, operators could create / update /
delete / assign / unassign teams but had no way to enumerate
them \u{2014} a gap the `rubix.user.delete` slice made glaring
(the cascade diagnostic literally tells the operator "the user
is a member of these N teams \u{2026}" and caps the echoed list
at 10).

## What landed

- `rubix/crates/rubix-spi/src/dto/team/list.rs` \u{2014}
  `TeamListRequest` (empty for v1), `TeamListItem` (id, name,
  optional description, `member_count`), `TeamListResponse`
  (summary + count + sorted rows), `REQUIRED_PERMISSION =
  "teams.read"`, and the five-field `DESCRIPTOR` with two
  sibling pointers (`rubix.user.list` for "wrong noun",
  `rubix.team.unassign` for "already have the id, want to
  mutate").
- `rubix/crates/rubix-spi/src/dto/team/mod.rs` \u{2014} added
  `pub mod list;`.
- `rubix/crates/rubix-tools/src/team/list.rs` \u{2014}
  `TeamListTool` reads the shared `TeamAdminStore`, sorts by
  name for stable rendering, projects each row to a
  `TeamListItem` (dropping the membership map, keeping the
  count), emits `rubix.team.listed` summary. No
  `ReversibleTool` impl \u{2014} read-only.
- `rubix/crates/rubix-tools/src/team/mod.rs` \u{2014} added
  `pub mod list;`.
- `rubix/crates/rubix-agent/src/registry.rs` \u{2014} imported
  `TeamListTool`, registered as a bare `Arc::new(\u{2026})`
  (no `wrap_rev`) immediately after the four reversible team
  verbs in the existing `// ---- tenant + team admin ----`
  block. Matches the placement of `TenantListTool` relative
  to the reversible tenant verbs.

Four unit tests in `rubix-tools`:

1. `empty_store_lists_zero_teams` \u{2014} fresh store
   returns `count = 0`, summary keyed `rubix.team.listed`.
2. `rows_come_back_sorted_by_name` \u{2014} three teams
   inserted out of order, response is alphabetical.
3. `member_count_reflects_membership_size` \u{2014} verifies
   the `member_count` projection runs against
   `TeamRow::members.len()`, not against assigned ids.
4. `description_round_trips_when_set` \u{2014} the optional
   description survives the round-trip.

## Decisions

- **`member_count` instead of full members map.** A team with
  thousands of members would balloon a single response payload
  if we echoed the full membership. The count is the
  information operators / admin UIs need 99% of the time; if a
  future verb needs per-team detail it should be
  `rubix.team.get` with its own surface (and pagination if
  membership ever grows past a sane bound), not a list
  response that's unbounded by definition.
- **`teams.read` permission, not the existing
  `teams.write`.** Read-only verbs get their own scope so a
  "team picker" role can be granted enumeration without the
  ability to mutate. Mirrors the
  `tenants.read` / `tenants.write` and `users.read` /
  `users.write` splits already in place.
- **Sort by `name` ascending.** Stable for rendering and
  matches the sibling pattern in `TenantListTool`. Id-sort
  would be deterministic but unhelpful to operators because
  ids are opaque.
- **Empty `TeamListRequest`** \u{2014} no filters in v1.
  Future filters (e.g. `member: Option<String>` to ask
  "which teams is this user in?") should be additive and
  default-skipped so existing callers keep working. Did NOT
  add `deny_unknown_fields` because no sibling list verb
  does, and the convention should stay consistent.
- **No `ReversibleTool` impl.** Read-only verb; no state
  changes to record. `Tool` only.
- **No new Pg migration / Pg integration test needed.** The
  verb reads through `TeamAdminStore`, which already has
  Pg coverage in
  [`2026-05-28-pg-team-admin-store.md`](2026-05-28-pg-team-admin-store.md)
  (`team_pg_test` 4/4 green). The verb's projection
  (`r.members.len()`) is a Rust-side operation on the
  trait-returned `BTreeMap`; if a future Pg-only failure mode
  could break it, the existing team_pg_test would catch the
  underlying `list()` regression first.

## Follow-ups

- **`rubix.team.get`** \u{2014} natural next surface if a
  caller needs the full membership list for a single team
  with per-row metadata (assigned_at_ms). Not built today
  because the cascade-resolve path (`team.list` \u{2192}
  pick id \u{2192} `team.unassign`) is sufficient for the
  user-delete unblock motivating this slice.
- **`rubix.user.get`** \u{2014} the third "missing read
  verb" once tenant.get is on the table. Defer until a
  consumer needs single-row lookups by id; today
  `user.list` returns the full row set and clients filter
  client-side.
- **Filter parameter on `team.list`** \u{2014} `member:
  Option<String>` would answer "which teams is this user
  in?" directly; could fold into the user-delete cascade
  diagnostic so it skips the cap when the operator drills
  in. Additive, defer until a consumer asks.

### Recorded-LLM test wiring lessons (for future tests)

- Use the upstream `starter_ai::testing::RecordingAiRunner` + `ScriptTurn`
  from `starter-ai/testing` feature. Do not roll a new fake.
- The propagator only routes **declared trigger slots** into a body's
  input map. Seeding `ALLOWED_TOOLS_SLOT` as initial state without
  declaring it a trigger means the body never sees it. Declaring it as
  a trigger means the body fires once per slot write at startup, so
  the script needs more turns than expected.
- The simplest test wire is: one trigger slot (`INPUT_SLOT`), no
  `allowed_tools` configured, and rely on the body's dispatch-by-name
  fallback (per `compute_visible_tools` comment: "if the model still
  emits a tool call by name the dispatcher resolves it against the
  host registry at call time"). The runner's advertised `tools_count`
  will be 0 with this wire — that's by design, not a bug to assert on.
- `starter-flow-nodes` is opt-in per node kind. Tests that touch the
  ai-agent body need `features = ["ai-agent", "tool-call"]`.
